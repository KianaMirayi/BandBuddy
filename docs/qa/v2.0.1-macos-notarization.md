## Result

The app was uploaded using Xcode's existing account session with Developer ID distribution. No new password, API key or certificate was created. Apple issued a notarization ticket, which was stapled to the exact submitted application before creating the final DMG and ZIP.

- `codesign --verify --deep --strict`: passed.
- `xcrun stapler validate`: passed.
- `spctl --assess --type execute --verbose=4`: accepted, source=Notarized Developer ID.
- ZIP extracted and DMG mounted read-only; the applications inside both packages passed the same signature, ticket and Gatekeeper checks.
- Updated model downloader and guitar model specs inside the DMG are byte-identical to the fixed source files.
- Hardened Runtime and Developer ID signatures are retained.

Artifacts: `release-macos/notarized-2.0.1/BandBuddy-2.0.1-macos-arm64.dmg` and `.zip`. The notarization ticket is stapled to BandBuddy.app inside both distribution containers. Checksums are in `SHA256SUMS-macos-arm64.txt` beside them.

The earlier `release-macos/signed-2.0.1` artifacts are retained as the original signed-only build. Use the notarized artifacts for distribution. Notarization does not change application behavior or resolve the recording-device enumeration issue documented in `v2.0.1-model-download-macos.md`.
